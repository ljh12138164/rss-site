# SEO 与 AI 时间轴来源优化

## Background

用户批准逐项落实 2026-10-11 SEO 审计与关键词建议，并补充时间轴来源显示。独立工作区基于最新 `origin/master`（336d8a8），分支 `feat/seo-followup`；原工作区的采集器未提交修改保持原样。

## Scope

- 持久化自动计算的索引资格，统一文章 robots 与 sitemap 筛选。
- 修正首页重复品牌名，完善 AI 来源页标题、简介与摘要回退。
- AI 时间轴列表与详情展示真实来源，支持多来源和缺失状态。
- 保留无限滚动，补充普通栏目/来源与时间轴的服务端历史分页链接。
- 普通详情增加同来源文章内链。
- 缓存 sitemap 目录及生成后的 XML，发布时失效，数据库失败不缓存缺页结果。

## Out of scope

不抓取知乎回答，不新增平台、Cron 或 UI 库；不批量生成文章、关键词列表或未经核验的中文译文；不修改 DNS、Cloudflare Dashboard 规则或站长账号。PR 由用户创建和合并。

## Acceptance criteria

- 已知知乎求回答、HN 链接占位、新华署名无可播放正文三个样本 noindex 且不在 sitemap；完整短讯和已支持的央视视频保留资格，正文补齐后自动恢复。
- 来源页标题/主标题说明具体内容，首页品牌不重复；description 缺摘要时使用可见正文回退。
- 时间轴首批 HTML 和后续 API 都返回去重后的真实来源；详情标题区域显示相同来源，未知/缺失不猜测。
- 关闭 JavaScript 后可点击历史分页，后续页 canonical 指向自身，非法游标不触发数据库查询。
- 详情同来源内链不包含自身或已判定不可索引的文章。
- sitemap 热请求复用缓存 XML，失败返回可重试状态；发布统一失效所有分片缓存。
- 相关测试、类型、格式、生产构建与真实数据验证通过。

## Feasibility

可行。云数据库只读探测成功，确认三种正文缺失形态；已有 Supabase REST、文章持久化、来源注册表和发布失效机制。新增数据库 generated column 在采集和人工编辑时自动计算，不要求修改采集器，也无需 sitemap 读取正文。索引规则只剔除确定占位/署名/请求回答形态，不采用字数阈值；它不评判文章原创性或所有内容质量。

现有缓存组件未开启，沿用项目兼容的 `unstable_cache`（Next 16 推荐新 use cache，但本轮不进行缓存架构迁移），缓存目录和 XML，禁止吞掉数据库错误。每个 XML 分片最多 2000 个 URL，Supabase 每次最多 1000 行，分片最多两个并发文章元数据请求。来源批量关联查询避免 N+1；历史页复用已校验的现有游标，保留快照和排序。

## Implementation

复用已批准的报刊式布局、紧凑封面列表和本轮优化清单。使用 Next 16.3.4、React 19.2.8、React Aria Components 1.17.0、Tailwind 4.3.3、lucide-react 1.40.0，不新增依赖。

已完整加载 UI Skills `dammyjay93/interface-design` 与 `ibelick/baseline-ui`。界面服务于快速扫读热点的读者；标题为主，来源为次，操作为第三层。沿用背景/文字/边框/primary tokens、现有字体、4px 间距单位、边框分隔和唯一强调色。保留来源与正文的真实层次，不新增卡片、渐变或动画。

修改已有首页、AI 栏目/来源、文章详情、时间轴列表/详情；历史页使用 `/archive/[section]/[[...source]]?cursor=...` 与 `/ai/events/archive?cursor=...`，从列表进入，返回栏目/来源或时间轴。只加入下一页和返回入口，复用 HotList / EventTimeline；验证目标包含桌面与手机、键盘、浅色/深色、加载/空数据/失败/缺来源状态。范围来自用户批准的优化清单，沿用已确认 UI，无新的视觉方向。

关键词落在实际标题、H1 和简介中：OpenAI 官方动态、ChatGPT 更新日志、新功能、AI 时间轴等与页面内容一致的词；没有增加 meta keywords 或虚构权重。关键词映射与原始证据见 [SEO 审计](../research/2026-10-11-seo-audit.md)。

两个 sitemap 路由显式动态响应，仅缓存成功的数据/XML；失败返回 503、no-store、Retry-After 60。发布统一失效 `sitemap` tag。来源范围限注册表中的文章来源，非文章榜单不生成详情 URL。

## Review and delivery

标准审查：沿用现有组件、类型、游标与来源注册表，无新依赖、不改采集器、不写入 Cron。规格审查：以上六项范围均完成；两个阻塞发现已解决并复查：时间轴 archive 被 proxy 误判为事件详情（新增回归测试），sitemap 可能静态缓存失败响应（改为动态路由）。无剩余阻塞项。

审查后接受的后续工作见 [路线图](../roadmaps/seo-followup.md)。拒绝添加 meta keywords、批量未经核验的翻译和任意字数阈值，它们不能代替可读内容。

实现提交 `772bc99` 已推送分支 `feat/seo-followup`，base `master`。按仓库要求，由用户创建并合并 PR；Web 尚未部署。CI 工作流仅在 PR、master push 或手动调用时触发，因此本分支 push 没有 CI 运行。云迁移已经生效且向后兼容，不要求同时更新采集器；部署后应复验线上 robots、来源和 sitemap。

## Risks

- 数据库索引资格是明确失败形态的过滤器，不能保证搜索引擎收录或排名。
- 本机 Supabase REST 之前不稳定；构建与界面需要必要时用真实云快照补充，准确记录验证范围。
- Cloudflare Cache Rules 属于现有用户运维范围；应用缓存命中不等同 Cloudflare HIT。
- 查询效果与原创选题需站长后台和人工编辑数据，不编造搜索量或资质。
