# AI 平台事件时间线开发记录

## Background

现有 `/ai` 把六个官方 AI 平台拆成独立来源区块，适合逐个平台浏览，却不容易快速回答“AI 最近发生了什么”。
本次将聚合页调整为按发布日期合流的事件时间线，同时保留来源频段和 `/ai/[source]` 详情页。

## Scope

- 将 `/ai` 改为六个官方来源的统一时间线，按真实 `published_at` 倒序排列并按上海自然日分组。
- 每条事件展示来源代码、来源名称、标题、发布日期与原文出口。
- 保留顶部来源频段，继续链接到各来源详情页。
- 提供可辨认的加载后空状态和读取失败状态。
- 适配 1440px 与 390px、明暗主题和键盘焦点。

## Out of scope

- 不新增、伪造或硬编码示例文章、占位事件及发布时间；Supabase 无真实记录时保持空状态。
- 不显示小时和分钟。部分上游只提供日期，当前数据模型也没有保存原始时间精度，不能暗示不存在的精度。
- 不增加手动刷新、自动刷新开关、筛选器或分页。
- 不改变首页 AI 摘要与 `/ai/[source]` 详情页。
- 不新增来源，不修改 Supabase 表结构、迁移、Cron 或抓取 API。
- 不引入新的 UI 依赖。

## Acceptance criteria

1. `/ai` 只渲染 Supabase 查询返回的真实 AI 文章，最近发布的事件优先。
2. 有日期的事件按 Asia/Shanghai 自然日分组；没有日期的真实事件进入“日期未知”组，不生成日期。
3. 原文链接继续经过 `/out`，并携带 `/ai` 返回路径。
4. 顶部六路来源频段可访问对应详情页。
5. 全部无数据时显示空状态；查询失败且无可用数据时显示错误状态。
6. 页面在桌面和移动端、明暗主题下信息层级清晰，无横向溢出，焦点可见。
7. Web 单元测试、格式、lint、类型检查与生产构建通过。

## Feasibility

- 云端 Supabase 现有 AI 分区共 102 条记录，六个来源均有数据且 102 条全部包含 `published_at`。
- 最近 7 天有 20 条，最近 30 天有 44 条，足以组成真实的近期时间线。
- 现有公开查询已返回 `source`、`title`、`url`、`published_at` 与 `position`，无需迁移或服务端写入。
- 当前环境没有暴露 UI Skills MCP，因此无法执行 UI Skills 注册表审查；本次使用现有设计 token、
  `frontend-design` 指引和仓库 UI 质量清单完成设计与验收，不声明 UI Skills 审查结果。

## Implementation

- 数据层新增 AI 时间线结果，将六路已有 Feed 合流后按发布日期倒序排列；页面只取最近 30 条，避免首屏后形成
  无边界长列表。
- 时间线使用现有信号橙作为纵向轨道与日期站点，沿用仓库的平面信号台语言；条目用分隔线组织，不复制参考图的
  大面积深色卡片、辉光或渐变。
- 桌面端日期作为独立窄列，移动端收进每个日期组头部；来源代码使用等宽字体，标题保持主要阅读层级。
- 静态服务端内容继续使用语义 HTML；没有引入不必要的客户端交互。

## Verification

- `pnpm --filter @rss-site/web test`：12 个测试文件、31 项测试通过；覆盖倒序合流、AI 来源过滤、上海日期
  分组、未知日期、空状态、错误状态和原文出口。
- `pnpm --filter @rss-site/web check-types`：通过。
- `pnpm --filter @rss-site/web build`：Next.js 生产构建通过，`/ai` 保持动态服务端渲染。
- Biome 对本次 6 个 TypeScript/TSX 文件检查通过，`git diff --check` 通过。仓库级 Web lint 仍会报告
  40 个未修改文件的既有 CRLF 格式差异；为遵守最小改动原则，本次没有批量改写无关文件。
- 本地页面连接云端 Supabase 返回 HTTP 200，服务端 HTML 含 30 个真实原文出口；抽查标题、来源和日期与
  云端记录一致，没有注入示例数据。
- 无界面浏览器已检查 1440px 桌面和窄屏响应式布局；时间线轨道、日期、来源与长英文标题正常，没有观察到
  横向溢出。明暗色继续使用现有全局 token，本次未改动主题系统。
- 标准审查与需求审查均无阻断发现；没有产生需要进入后续 roadmap 的改进项。

## Risks

- 不同来源的发布时间精度不同，因此仅展示日期并明确以日分组。
- 时间线只依赖公开 `hot_items` 查询，不依赖 `source_status`；查询整体失败时显示错误状态，查询成功但没有记录时
  显示空状态。
- 当前列表限制为最近 30 条，它是近期视图而不是数据库全量归档。
