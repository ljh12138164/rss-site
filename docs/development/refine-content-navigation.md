# 内容导航与界面文案重构

## Background

当前界面把抓取频率、来源代码、更新时间和内部数据约束直接展示给读者，形成了“信号台”“频段”“窗口”等
难以理解的产品语言。分区页同时使用横向来源条和两列来源卡，平台切换不直观；暗色主题的红色强调又让普通
加载状态看起来像错误。用户明确要求删除图片区、抓取时间、2H/6H 和实现说明。最新参考图进一步确认，
分区标题下方应直接列出 GLM、Gemini 等真实内容来源，文案使用日常中文。

布局参考 [Readhub 热榜](https://readhub.cn/hot) 的频道层级、[NewsNow](https://newsnow.busiyi.world/) 的高密度
浏览和 [Folo](https://folo.is/) 的完整来源名，只复用信息架构原则，不复制视觉或文案。

## Scope

- 站名与 metadata 从“热点更新.”改为“AI 热榜”，对应 AI 为主、其他分区为辅助的真实定位。
- 删除页面上的抓取时间、2H/6H、来源代码、英文装饰标签、“信号台/频段/脉冲/窗口”等内部词。
- `/ai`、`/technology`、`/news`、`/social`、`/finance`、`/games` 及其来源详情采用统一的水平来源导航。
- 桌面端在标题下方直接列出来源并允许换行；移动端横向滚动，保留键盘与触摸可达性。
- 首页保留分类和真实文章，但移除横向来源带、图片、技术说明和装饰性编号。
- 全部文章列表移除图片预览；暗色和亮色主题统一改用冷蓝强调，加载骨架只使用中性灰。
- 将空态、错误态与来源简介改成面向读者的简短中文。

## Out of scope

- 不改抓取频率、Cron、Supabase schema、数据保留规则或来源顺序。
- 不增加新路由、筛选状态、搜索、无限滚动或新的 UI 依赖。
- 不部署前端，也不配置 Docker、PM2、GitHub Actions 或 Cloudflare。

## Acceptance criteria

- 公开页面不再出现 `2H`、`6H`、`Refresh window`、`更新于`、`信号台`、`频段`、`脉冲`或来源代码。
- 六个分区页和 36 个来源详情都在标题下方提供同一套来源导航，当前位置通过 `aria-current` 和蓝色下划线表达。
- 导航使用平台的常用短名称，例如 `GLM`、`Gemini` 和 `B 站`；移动宽度下可横向滚动且正文不发生页面级横向溢出。
- 文章标题、摘要、作者和原文跳转仍可用，但不渲染任何远程图片或图片占位。
- 加载骨架在暗色主题中为中性灰，不使用红色；交互强调色在两种主题中均有可读对比度。
- 空数据只显示“暂无内容”，读取失败只显示“暂时无法加载，请稍后再试”，不暴露 Supabase 或采集实现。
- Web 测试、格式、lint、类型检查和生产构建通过，并检查桌面、移动、明暗主题与键盘焦点。

## Feasibility

结论：可行。

- 现有 `/分类/[source]` 路由和静态来源注册已经提供平台选择所需的数据与 URL，无需客户端筛选状态。
- 六套分区页结构重复，可通过一个 `SectionOverview` 与一个 `SourceNavigation` 收敛；详情页继续复用
  `SourceDetailView`，只替换其导航和头部。
- Next 16 的 `<Link>` 会为可见来源链接提供客户端导航与适用的预取；现有各动态路由已有 loading UI。
- 水平导航不需要客户端筛选状态；每个链接继续进入既有 `/分类/[source]` 路由。
- `apps/web/next-env.d.ts` 由正在运行的 `next dev` 更新为 `.next/dev` 类型路径；仓库 Next 指令要求随本次
  Web 变更提交，避免开发服务器持续重写工作区。
- UI Skills registry 未暴露要求的 `dammyjay93/interface-design` 与 `ibelick/baseline-ui` 获取工具；本轮明确
  使用 `frontend-design`、仓库 React Aria/Tailwind 现状和 UI quality 清单作为回退，不声明 UI Skills 审查。

## Implementation

- 界面契约：读者是希望快速浏览 AI 与互联网热点的人；主操作是选择平台并打开原文；焦点永远是文章列表。
- Palette：Paper `#f8fafc`、Ink `#172033`、Blue `#2563eb`、Night `#0f172a`、Mist `#e2e8f0`、Slate
  `#64748b`。蓝色只标记当前导航、排名和交互，不承担加载或装饰。
- Typography：延用系统中文无衬线用于正文与标题，等宽字体只保留文章排名；不再把普通标签写成终端输出。
- Layout：所有宽度均为 `标题 → 来源导航 → 阅读区`；桌面导航可换行，移动端只让导航容器横向滚动。
- Signature：标题下方的一行真实来源名；只用当前项的蓝色下划线强调选择，不再使用代码、频率或装饰条。
- Copy：首页改为“看看今天 AI 圈发生了什么”；各分区说明直接说“最近发布了什么”“正在关注什么”或
  “最近都在聊什么”，不再描述内部数据组织方式。

## Verification

- 参考站点只用于核对信息架构：Readhub 将频道与内容列表分开，NewsNow 强调高密度浏览，Folo 使用完整来源名；
  实现没有复制它们的品牌、组件或文案。
- Web Vitest 21 个文件、50 项测试通过；断言禁止公开 HTML 出现图片、抓取时间、2H/6H 和“信号台”，
  并验证水平来源导航显示 `GLM`、`Gemini` 等常用名称和正确的当前项语义。
- 全仓格式、Biome lint、类型检查与 Next 16.3.4 生产构建通过，构建生成 38 个页面并保留专区 RSS 路由。
- 使用本地 Next 服务和现有云端只读数据，通过纯 HTTP 检查 `/`、六个分区与 `/ai/glm`，八个路由均返回
  200；`/ai` 服务端 HTML 包含“内容来源”、`GLM` 和 `Gemini`，且不含“信号台”“频段”、刷新窗口、
  2H/6H 或“更新于”。未操作桌面或可见浏览器窗口。
- 响应式代码审查覆盖移动横向 nav 容器自身滚动、桌面换行、44px 链接高度、`aria-current` 与焦点轮廓。
  暗色骨架使用 `--muted: #1d293d`，不再引用红色 accent。
- 遵照用户要求未操作桌面或可见浏览器窗口；因此不声称完成交互式截图对比，交付以前述服务端 HTML、
  响应式样式审查和用户本地页面复核为准。

## Review

- Standards：六套分区页收敛到 `SectionOverview`，六套 loading 收敛到 `SectionLoading`，来源详情复用同一
  `SourceNavigation`；未增加客户端状态、依赖或平行设计系统。
- Spec：站名、水平来源导航、无图列表、中性加载和口语化文案均已覆盖；抓取、Cron、数据库和部署配置未改动。
- Visual critique：初稿仍可能靠缩写和频率制造“技术感”，最终只保留完整平台名、文章排名和一个冷蓝交互色；
  结构承担识别作用，避免再出现装饰性终端语言。
- Review fix：生产构建前 `next dev` 自动生成的 `next-env.d.ts` 变化在 `next build` 后恢复，最终不把环境切换
  产生的路径差异提交到分支。
- Review fix：最新参考图将原桌面侧栏修正为标题下方水平来源导航；内容继续单列展示，避免侧栏占用阅读宽度。
- Rejected：不重新加入图片占位、更新时间、刷新频率、英文 eyebrow、来源代码、数据实现说明或首页装饰编号。
- 本轮没有需要新建 roadmap 的评审后续；服务器部署仍按既有 `docs/roadmaps/production-launch.md`，且只有用户
  明确批准后才实施。

## Risks

- 首页同时展示 36 个来源仍然较长；本轮通过压缩头部、移除图片和使用单列来源组改善，不额外引入分页。
- 平台名较长时移动端导航必须允许横向滚动；只使用读者熟悉的短名称，不能退回 `OA`、`GM` 等来源代码。
- 删除图片只影响呈现，数据库仍保留 `image_url`，以后如重新引入图片无需迁移。
