# 管理后台与内容发布流程

## Background

用户选择架构报告第一项：合并采集更新和文章编辑后的发布流程。用户同时要求给指定邮箱授权，并将简陋的管理页改为标准 dashboard。分支 `feat/admin-dashboard-publication` 基于最新 `origin/master` `2108484`；起始工作区干净。

## Scope

- 合并缓存失效、后台发布与安全失败日志；保留现有路径政策及外部发布代码。
- 优化现有 `/admin`：侧栏导航、账户区、真实采集概览、来源状态表、文章列表和编辑工作区。
- 授权用户指定的现有账号，保留其他 app_metadata；不改变数据库结构或普通用户权限。

## Out of scope

新来源、Cron 调整、手动采集、用户管理、历史趋势图、新 UI 依赖和生产部署。

## Acceptance criteria

- 采集通知缓存失效失败仍返回 500；已经保存成功的编辑不因发布失败返回保存失败。
- 编辑标题后刷新旧、新详情路径；仅失效成功后安排外部发布，不泄露错误详情。
- 看板概览与来源表使用相同分区过滤；正文覆盖率按样本总量计算，不平均各来源百分比。
- 加载、权限、网络、空列表和保存结果分别表达；统计不可用时不展示假零值。
- 桌面、390px 手机、明暗主题无页面横向溢出；表格可在容器内滚动。

## Feasibility

可行。最新代码已包含采集看板和只读 RPC；无需迁移。发布路径和外部动作已有集中模块，新增执行协调即可。关键约束是两种请求的错误语义不同、编辑旧路径失效、统计过滤范围一致，以及权限更新后的旧 JWT 需要刷新。

GitHub 直连失败；通过本机现有代理成功 fetch，已确认最新基线，避免覆盖截图中已有看板。

## Implementation

复用架构报告、article-admin 和 reading-productivity 既有设计。用户先选择仅改善样式，随后明确要求按截图实现标准 dashboard，最终方向按后者落实。范围仍为现有 `/admin`，没有新增路由或功能。

已读取项目 frontend-design、Supabase、codebase-design、TDD 及 UI Skills `dammyjay93/interface-design`、`ibelick/baseline-ui`。继续使用 Next 16.3.4、React 19.2.8、Tailwind 4.3.3、React Aria 与 Lucide；复用语义主题、ActionButton，简单表单保留原生控件。

界面对象是检查采集和修正文章的站点管理员。编辑区为焦点，采集概览用于发现异常；采用现有 slate/teal 主题、细边框和分组间距。桌面侧栏与工作区、列表与编辑双栏；手机导航横排、内容上下排列。状态不通过装饰性颜色或虚构数字表达。

已使用 Supabase 插件将用户指定账号的服务器角色从 `admin` 调整为现有规则要求的 `article_admin`，复查已生效，并在回滚事务中用 authenticated 与该角色验证采集运行记录可读。账号需退出并重新登录刷新 JWT。仅记录角色变更，不提交邮箱、用户 UUID 或凭据。

## Verification

- Web 全量 Vitest：70 个文件、264 项测试通过；API 85 项、signals 7 项通过，共 356 项。新增测试覆盖发布执行顺序、缓存失败、后台发布失败、旧新标题路径、分区统计、缺失来源与正文加权。
- Web `tsc --noEmit`、8 个变更代码文件 Biome、`git diff --check` 通过。使用已安装的 Node CLI，避免 pnpm 启动时重复安装依赖。
- Next 生产构建使用现有 `.env.local`，编译、类型检查和 62 个静态页面生成通过；没有部署生产站点。
- 云端指定账户角色复查为 `article_admin`；回滚事务内使用 authenticated JWT claims 验证采集记录及 `get_ingestion_health()` 可读，RPC 返回 40 个来源。
- 浏览器使用本地 Auth 替身及云端公开数据快照：登录、科技分区概览与来源表一致、文章选择、标题保存反馈、搜索空结果与清除通过。保存只修改本地快照。
- 390×844 手机亮暗主题没有页面横向溢出（页面宽 375px、视口 390px）；导航横向滚动、列表与编辑区上下排列，来源表在有限高度容器内滚动，键盘可聚焦容器。桌面显示侧栏及双栏编辑区。截图保存在本机临时文件，未提交测试用户或快照。
- 独立代码审查无阻塞项；没有接受的后续项，因此不创建空路线图。真实账号浏览器登录仍需用户刷新会话后验收。

## Risks

真实管理员浏览器会话没有提供密码，不能冒充已经验证实际登录；通过云端权限查询和本地 Auth/数据替身验证对应部分，并分别记录。页面需要发布才能在线上出现。
