# 首页全部文章与滚动加载

## Background

用户澄清首页应像子分区的“全部”页显示统一列表，而不是六个分区列表；必须显示全部内容、按时间排序并滚动加载。继续当前分支，沿用用户明确要求跳过测试。

## Scope

- 首页“全部”读取六个分区已收录的文章，包含历史收录，不再每源仅取一条。
- 复用 HotList 的连续编号、标题、摘要、来源图标和日期；保留横向分区入口。
- 每次读取 30 条，接近底部继续获取下一页；提供键盘可用的加载按钮、失败重试、空态及末页提示。
- GitHub Trending 通过独立开源榜入口访问，不混入文章。

## Out of scope

子分区页面分页、数据库迁移、Cron、生产部署与推送。

## Acceptance criteria

首页只有一个跨来源列表；按 published_at 降序、id 升序，空日期最后；分页保持相同顺序，不重复追加同一 article ID；下一页失败保留已有条目并允许重试；来源链接指向所属分区，新闻仍进入站内详情。

## Feasibility

复用已公开只读的 signal_articles 和 Supabase 客户端，无新增依赖或权限。服务端首屏读取 30 条，后续 /api/articles 按日期与 UUID 游标续取，读取额外一条判断是否有下一页。固定 first_seen_at 上界，避免浏览期间新插入文章挤动分页；刷新页面可读取新文章。相比 offset 分页无需逐页跳过已读记录。

## Implementation

沿用用户截图确认的大标题、说明、横向导航与单栏平面列表，复用现有语义色、React Aria ActionButton。使用 IntersectionObserver 接近底部加载、请求互斥、卸载取消和 ID 去重。无 IntersectionObserver 时保留手动加载。游标参数限定日期和 UUID 格式，不接受任意过滤表达式。

## Verification

按用户要求，不运行测试、类型检查、构建或浏览器测试。仅格式化本次文件并静态阅读修改；同步替换不再适用的首页测试夹具，未执行。之前 GitHub 分离功能的验证不覆盖本次修改。

## Risks

尚未验证真实分页请求与滚动交互。已有文章的发布日期若被上游纠正，跨页位置仍可能变化；客户端去重可避免重复显示，但刷新后才保证看到完整的最新排序。数据库历史保留策略决定可读取的历史范围。

## Review

静态检查覆盖游标边界、空日期、并发请求、失败重试及跨分区链接。没有新增已接受的后续功能，不创建空 roadmap。
