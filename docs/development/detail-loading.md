# 详情加载边界修复

## Background
栏目布局在详情及 AI 时间轴路径不提供 SiteShell，而这些路径缺少自己的 loading，导致继承的列表骨架铺满页面且缺失页头。

## Scope
覆盖六栏目文章详情、AI 事件详情及时间轴。复用已接受的新闻详情骨架和 SiteShell 设计，正文宽度对齐阅读页；不改变数据请求、缓存策略和正常页面结构。

## Feasibility
可行。使用路由级 loading 就能在数据等待期间提供对应外框，不需全站布局重构或新增依赖。栏目列表依然由既有布局持有外框，避免双重页头。

## Acceptance criteria
所有独立阅读页和时间轴在加载时保留唯一页头、main、页脚，文章骨架限制在阅读宽度内。所有对应路由显式声明 loading。

## Implementation
共享 ArticleLoading，七个详情路由引用；AI 时间轴使用带标题和 SiteShell 的列表骨架。无 API、数据库或部署配置变更。

## Verification
路由加载组件渲染回归覆盖七个详情入口和时间轴，验证唯一外框、正文宽度和无障碍加载状态。Web 35 个测试文件、116 项测试通过；Web 类型检查、修改组件 Biome 检查和 git diff --check 通过。逐项审查确认全部六栏目详情与两个事件入口已覆盖，未修改栏目列表布局，无阻断发现。

## Risks
加载边界修复不改变上游数据延迟；真实线上慢网导航需要发布后验收。审查未产生额外路线图事项。
