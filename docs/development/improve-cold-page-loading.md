# 首次访问加载优化与文章图表修复

## Background

用户反馈首次访问页面偶发长时间等待、刷新后恢复，并要求修复掘金文章中的 Mermaid 源码直出。复现文章 ID：`597155a6-be78-41ac-b135-7d0ef37cb599`。

## Scope

- 优先优化未访问文章的服务端数据加载，消除可独立执行查询的串行等待，并跨同来源文章复用推荐链接查询。
- 将正文中的 Mermaid 代码渲染为图表，兼容已入库、丢失语言标记且引号被双重转义的历史内容。
- 通过真实公网与源站请求、容器指标、TLS/代理日志排查首次访问慢，记录证据。

## Out of scope

不重写文章正文，不改数据库、采集任务、ISR 周期或 Cloudflare TLS 模式。用户已要求暂停 TLS 排查。取消 Bun `--smol` 此前已独立交付至 `feat/remove-bun-smol`，但尚未合并；本分支同时包含这项已确认的启动配置修改，合并本分支即可一并生效。

## Acceptance criteria

- 首次文章预检中的 tombstone/可见性查询并发，正文/同来源文章查询并发；保留硬 404/410、删除优先及查询失败时 503 的行为。
- 同来源推荐链接共享缓存，排除当前文章且最多返回四条；继续使用现有来源状态失效标签，无新增失效通道。
- 用户文章的 `flowchart LR` 和 `flowchart TD` 显示为图，引号与中文标签正常。
- 普通代码块保持源码；无图表文章不加载 Mermaid；图表失败时保留可读源码。
- Mermaid 使用严格安全模式和输入规模限制，外部正文不能开启脚本、点击回调或放宽渲染安全配置。
- 文章切换、组件卸载和明暗主题变化不会留下旧图表。
- 回归测试、类型、变更文件格式、构建及可行的浏览器明暗/桌面/移动检查通过。
- 慢请求结论区分 TLS 建连、等待响应、正文传输与页面生成；未复现的历史 CF 错误不冒认根因。

## Feasibility

加载优化可行：真实源站首次 MISS 7.39s，随后 HIT 1.12s。分解只读 Supabase 请求测得 tombstone 2000ms、存在性 1256ms、正文 1010ms、同来源列表 1272ms；同场并发对照为状态两查询 1127ms、正文/同来源两查询 637ms。这证明数据串行链存在可消除的网络往返；这些单次对照受连接复用影响，不能当作上线后的固定加速比例。

保留现有 ISR、硬状态预检与 UI 决定，优化查询调度；来源列表读取前五篇后在内存排除当前 ID，沿用 `news-status:<source>` 标签和 6h 周期，现有采集/编辑失效逻辑继续生效。图表方案如下。

可行。现有 `ArticleHtmlBody` 是客户端正文增强入口；文章 HTML 已在服务端清洗。生产文章中保存了未标注语言的 `<pre><code>flowchart ...`，其中引号为 `&amp;#34;`。当前清洗会删除代码语言 class，客户端没有 Mermaid 渲染器，两者共同导致源码直出。

## Implementation

- 可见性预检并发读取 tombstone 与存在性，仍先判断 tombstone 结果再判断存在性，保留删除优先及失败关闭。
- 渲染文章时并发读取主文章和同来源列表，路由校验仍先于数据库调用；metadata 与正文继续复用同一 React 请求缓存。
- 同来源列表缓存最近五条，使用现有来源失效标签，返回前排除当前文章并截取四条。不同冷文章复用同一数据缓存，数据库错误不转成可缓存的空成功结果。
- Docker 启动移除两处 `--smol`，保留预处理成功后启动服务的顺序。
- 正文仅保留指定 Mermaid 语言 class；客户端识别图表后动态加载渲染器，兼容无语言标记的历史内容。严格安全配置及输入/边数限制不能被正文指令覆盖；解码后的内容只作为文本传入渲染器，不执行回调。渲染失败保留源码，主题变化时还原原始节点并重绘。

### Reused interface decisions

复用 `article-translation.md` 与现有正文设计：唯一改动表面为现有文章内容区，不新增路由、弹窗或导航。读者需要理解文章流程，图表从属于正文标题层级；使用现有 `article-content`、背景/边框/正文语义 token、字体与 4px 间距基础，保持平面阅读布局。加载和失败保留源码，成功显示图；桌面与移动端均约束宽度，复杂图可横向滚动，无新增动画。

已读取 UI Skills `dammyjay93/interface-design` 和 `ibelick/baseline-ui`。渲染依赖新增经本次用户明确批准，沿用既有界面决定，无需重复整体视觉评审。

## Review and delivery

已对照仓库规则与验收项检查最终差异：查询并发不改变返回状态优先级；推荐缓存按来源隔离、保留失效标签；仅新增 Mermaid 及其传递依赖，没有升级现有依赖；图表安全配置禁止正文覆盖，保留源码回退和卸载清理。没有未解决的代码阻塞项，没有接受的范围外跟进项，因此不建立空 roadmap。

交付分支为 `feat/improve-cold-page-loading`，目标为 `master`。按仓库规则由用户创建并合并 PR；CI 的完整镜像构建和运行验证必须通过后再合并。本分支尚未部署，1.76s 是独立查询对照结果，并非修改后整页或线上性能承诺；合并发布后才可复测新的冷页 MISS。

## Risks

历史 CF 错误码和时间缺失，目前未复现 525/526，需以错误日志和实际请求为准。浏览器按需下载图表依赖有首次加载成本；不能为图表把服务端页面生成变重。第三方图表语法异常必须回退源码，不能阻断整篇文章阅读。
