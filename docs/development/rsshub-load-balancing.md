# 现有 RSSHub 抓取分流

## 背景

生产采集默认经 `rss.ljhboard.cn`。候选路由文档记录了用于分担 Vercel 请求量的第二个实例 `rss1.ljhboard.cn`。两个实例独立部署，路由可用性可能不同。

## 范围

以[候选路由文档首次入库](https://github.com/ljh12138164/rss-site/commit/32489cc)前的 `604c8dd` 为范围基线。仅从当时已配置且仍在运行的 RSSHub 抓取路径中选择两端均能正常返回数据的路径分流。直接订阅、知乎 Cookie 维护、模型排行和候选文档之后接入的路径继续使用各自现有的抓取入口。

## 验收标准

- 选定路径固定优先使用备用实例。请求失败时用原 URL 重试一次，保留路径和查询参数。
- 多 Feed 来源按路径独立分流，并保留原有合并及失败写入语义。自定义 `RSSHUB_BASE_URL` 保持独立。
- 对两个公网实例做匿名只读探测，并通过采集管线回归测试。

## 可行性

定时任务和手动信号采集共用 `runIngestionPipeline`，可在抓取层完成分流。现有普通 Feed 单次抓取超时为 30 秒。两次普通 Feed 请求的上限为 60 秒，低于 `pg_net` 的 180 秒请求预算。

## 实现

对基线内 40 条定时 RSSHub 路径固定分配首选实例，其中 19 条走备用实例。按现有 Cron 频率推算，基线范围两端各 100 次首发请求／天。加上后来接入的路径，全部定时 RSSHub 首发请求预计主实例 136 次／天、备用实例 100 次／天。估算未计手动抓取和失败重试。

分配以包含查询参数的完整 Feed URL 为准。OpenAI News 分到备用实例，OpenAI Developers Blog 留在主实例。知乎热榜继续走已配置 Cookie 刷新的主实例。

## 验证

- 2026-11-18 公网匿名实测。入选 19 条路径在双实例均返回 HTTP 200，经生产解析器得到非空条目，逐路条目数一致。备用实例的 OpenAI Developers Blog 返回 HTTP 404。
- `pnpm test` 323 项通过，22 项依赖数据库或 Redis 的集成测试由本地设置跳过。`pnpm check-types`、变更文件 Biome 检查与 `git diff --check` 通过。
- 按仓库标准和范围复核差异。无阻塞发现或已接受的后续开发项。

## 风险

备用实例独立发布，路径的短期异常会增加回退请求和采集时延。
