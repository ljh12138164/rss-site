# 事件式日报与线上回归修复

## Background

2026-11-07 用户要求拉取最新代码并回归线上日报，随后指出固定六分区出现大量“本期未收录”，要求日报直接总结发生的事件并引用站内文章。基线为 master a131561；原目录分支 feat/daily-event-digest。

生产核验：11 月 5、6 日已发布且通知 accepted；11 月 7 日自动任务三次失败，08:14:31 上海时间终止，错误 primary_invalid_response，公开页仍显示 11 月 6 日。生产实际模型为 gemini-3.5-flash-lite，已取消旧文档中的 GPT 兜底和启用开关。对当天冻结材料进行不入库的真实生成重放，23 份材料返回 3 条事件，但因 Unknown source or incompatible section 被拒绝。

## Scope

- 修改既有 /daily 与 /daily/[date] 共用正文，不新增页面。
- 按重要性连续显示事件摘要，以来源分区作简短标记；移除固定分区目录和空分区占位。
- 引用优先使用有标题的站内文章链接；文章被清理时回退快照原文。
- 配套 ai-base 修复日报生成的已复现协议问题；保留事实写作要求和引用、预算、租约校验。

## Out of scope

新来源、数据库迁移、重新生成既有成品、替换模型、自动部署及直接改写生产任务。

## Acceptance criteria

- 单条、多条、缺少四个分区时都只展示真实事件，没有“本期未收录”或“本期重点见头条”。
- 单一分区的其他事件仍完整展示；事件标题、摘要、锚点和来源均保留。
- 本站存在文章时引用可读的文章标题和站内地址，不存在时仍可打开原文。
- 最新、往期、日期导航与加载/错误状态保持原行为，桌面和手机均可读。
- 生成修复具备失败前后测试及真实冻结材料的非发布验证，不把模拟结果当生产出刊。

## Feasibility

可行。展示组件已接收按重要性排序的 stories 及经过数据库存在性检查的 articleLinks，无需新查询、依赖或协议版本。沿用 daily-report.md 已确认的原路由、桌面侧栏/手机单列、橙色语义主题、Next 16.3.4、React 19.2.8、Tailwind 4.3.3 和 React Aria 1.17.0。本次仅将正文改成事件流，复用原版式与交互的确认；用户已明确要求该变化。

## Implementation

UI 工作简报：读者快速了解前一天发生的事，再打开引用报道；焦点为头条和连续事件正文。沿用背景/前景/primary/border tokens、既有标题字体和正文层级、4px 间距基准，分隔线沿用现有细线，不添加动画、卡片或 UI 库。往期导航保持原位置。已加载 UI Skills interface-design 与 baseline-ui，阅读安装版 Next Server Components 指南；应用 ponytail 原则，删除空结构而非补造内容。

## Verification

修复前线上：/daily、11-05、11-06 为 200；11-07 与非法日期 2026-02-30 为 404/no-store；未鉴权内部接口为 401。历史导航实际浏览器跳转成功。既有日报测试 13 通过、8 项真实服务集成因环境缺失跳过。

修复后验证（2026-11-07 实现，11-08 完成交付检查）：

- `pnpm test`：Signals 8、API 114、Web 177，共 299 项通过；16 项已有 PostgreSQL/Redis 集成因本地服务未配置跳过。最终定向复跑正文/读取/代理/内部接口 20 项通过。
- `pnpm check-types` 通过；变更文件 Biome 无错误/警告。全仓 `pnpm lint` 在临时将检出文件 CRLF 规范为 LF 后通过，随后恢复原始字节，没有提交无关换行改动。
- 使用生产 11-06 真实公开成品在临时本地 Next 页面渲染，1440px 和 390px 均无横向溢出；手机明暗主题、日期导航、键盘展开往期和事件锚点通过。正文完整保留两条事件，未出现任何空分区；引用指向有标题的站内文章。单事件及原文回退由渲染测试覆盖。
- 本地预览路由已删除，开发服务停止，视口覆盖已恢复。构建首次被预览生成的过期 dev 类型引用阻断，删除该临时类型文件后重新构建通过：58/58 静态页面完成，Early Hints 和 Service Worker 生成成功，无遗留预览路由。
- ai-base 的当前修复代码在生产容器内以独立 Bun 进程重放 11-07 的同一冻结输入，完整校验通过：4 条事件、4 个来源，AI/科技各 2 条；极客公园代表稿正确归为 technology。生成耗时 64,869ms、2 次尝试，成功响应用量为 22,704 输入 / 736 输出 token。没有提交任务、发布报告、修改冻结输入或重启生产服务。
- 该重放验证旧 editor-v2 冻结 prompt 与新结构化响应协议兼容；新 editor-v3 提示词和来源分类职责已通过代码及契约复核，不将单次重放等同于完整事实准确性保证。

复查结论：事件顺序、锚点、单条展示、标题引用/原文回退与 v1 成品兼容，无剩余代码阻塞项。没有接受的范围外跟进，不创建空 roadmap。

## Risks

生成模型仍可能出现事实偏差或上游故障；不能通过隐藏空分区保证模型出刊。生产任务及公开成品不在本地实现中修改；合并部署后另行重跑缺失日期并核对成品。

## Delivery

两仓分支均为 `feat/daily-event-digest`，base 均为 `master`。按仓库规定准备并推送分支，由维护者创建和合并 PR；优先部署 ai-base 后再部署 rss-site。没有数据库迁移、新密钥或新来源 Cron。
