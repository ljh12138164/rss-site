# 首页分区预览索引

## Background

首页每个分区读取 3 条最新文章，按 `published_at DESC NULLS LAST, id` 排序。生产 PostgreSQL 执行计划显示，现有 `(section, source, last_seen_at)` 索引定位候选后，新闻预览读取约 3.54 万行，耗时 0.85 秒，社交预览读取约 2.15 万行，耗时 1.55 秒。生产只读检查约有 8.3 万条文章，主表堆约 121 MB。

## Scope

新增一条 ECS PostgreSQL 业务迁移，为 `signal_articles` 添加适配首页排序的 B-tree 索引。基于已合并日报修复的 `master`（`3f436a4`）。

## Out of scope

首页 SQL、来源筛选、显示顺序、缓存策略及现有索引。

## Acceptance criteria

- 迁移可在现有发布事务中执行并重复回放。
- 应用角色可按原查询返回相同的文章和顺序。分区、来源、空日期与同时间戳均按现有规则处理。
- 新闻和社交查询可以按新索引有序扫描，取够 3 条后停止。

## Feasibility

沿用用户已确认的索引 `(section, published_at DESC NULLS LAST, id)`。第一个键定位分区，其余键直接满足排序。生产另有仅覆盖 `is_indexable` 文章的部分索引，首页查询的结果范围包含该索引之外的记录。

发布脚本在同一事务中回放业务迁移。PostgreSQL 支持在该事务中执行普通 `CREATE INDEX`。新索引与现有选择计划兼容，由优化器估算成本后选用。

## Implementation

`026-home-preview-published-index.sql` 使用 `CREATE INDEX IF NOT EXISTS`，由现有发布流水线执行。新装与恢复环境通过同一发布迁移获得索引。

## Verification

- 隔离 PostgreSQL 18 导入约 8.5 万条模拟文章，主表堆 134 MB。直接执行迁移文件，首建事务耗时 77 毫秒，重复执行保留原索引 OID。索引经 PostgreSQL 标记为有效，占 4,248 kB。
- 用只有 SELECT 权限的角色运行六个分区的原查询，建索引前后返回同一组有序文章。新闻由读取 35,072 条候选转为新索引直接取 3 条，社交由读取 21,272 条候选转为取 3 条并跳过一条未选来源。科技、财经和游戏也使用新索引，AI 在该模拟数据上选择旧计划。
- 渲染部署 SQL，确认新迁移进入现有事务。本地建索引耗时仅用于评估验证环境，生产建索引时间与执行计划仍需上线后实测。
- 已按原查询、迁移顺序和回放要求自查，无衍生路线图。

## Risks

首次建索引在迁移提交前会阻塞文章表写入，建索引耗时受生产磁盘负载影响。新增索引占用磁盘空间并增加文章写入时的索引维护成本。
