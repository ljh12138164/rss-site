# 后续热点分类调研

## Background

站点已有科技、国内新闻、AI 平台和社交热点四个分区。此次先研究还能稳定抓取哪些独立分类，为下一轮
实现确定真实来源范围，避免先建空页面、使用假数据或把需要登录态的路线加入 Cron。

详细路由、条目数与失败证据见
[后续热点分类与 RSSHub 来源调研](../research/additional-hot-categories.md)。

## Scope

- 基于 RSSHub 官方源码识别财经、游戏、体育、影视文化、科学研究、生活消费和汽车候选来源。
- 匿名请求当前自建 RSSHub，记录 HTTP 状态、非空条目、发布时间与图片覆盖情况。
- 按可用性、内容语义和现有时间线模型给出优先级与首批来源建议。
- 只提交研究与交接文档，不修改 Web、API、数据库、RSSHub 部署或 Cron。

## Out of scope

- 在用户确认前新增分区页面、来源注册、数据库白名单或计划任务。
- 对云端 Supabase 写入测试数据，或用本地 Docker 替代未来的云端生产验证。
- 配置 Cookie、Token、浏览器运行时或其他新秘密。
- 将“最新发布”“编辑头条”“实时快讯”“排行榜”合并为虚构的统一热度分数。
- 修复本次发现的 RSSHub 503 或超时路线。

## Acceptance criteria

- 候选分类至少覆盖内容价值、来源数量、匿名可用性、时间字段和图片字段。
- 每条推荐路线在当前部署返回 HTTP 200 和非空真实数据。
- 失败、超时、需要秘密和缺少发布时间的路线明确标注，不进入默认实现范围。
- 给出一个可以直接进入下一轮设计的推荐分类和首批来源组合。
- 不产生业务代码、生产数据库写入或 Cron 变更。

## Feasibility

结论：财经可直接进入下一轮实现设计，游戏可作为后续第二批。

- 41 条匿名候选中有 29 条成功；财经 7/7，游戏 7/9，是来源数量与数据质量最强的两类。
- 财经可从 6 个不同平台组成首批，合计 88 条，全部带发布时间；现有通用 RSS 解析、分区页和 Cron
  模型可以复用。
- 游戏核心四路新闻合计 80 条并全部带时间，图片覆盖 78/80；Steam 热销榜无发布时间，需要单独的
  “榜单快照”展示语义。
- 体育数据完整但只有两个稳定综合平台；影视文化封面完整但缺少发布时间；科学研究混合趋势与最新；
  生活消费定位过宽；汽车只有一路稳定来源。
- 本次不需要 Supabase 技能或云端连接，因为调研阶段没有数据库任务。实现阶段必须重新执行云端生产门禁。

## Implementation

本轮没有业务实现。推荐下一轮以 `finance` 为独立分区，并先确认页面入口与展示面：

- 六路来源：华尔街见闻、财联社、金十数据、第一财经、证券时报、同花顺财经。
- 保留各来源自己的“热榜 / 头条 / 快讯”标签和顺序，不计算跨平台排名。
- 快讯无图是正常内容状态，复用现有通用占位，但不生成假封面。
- UI 方案确认后再新增 `/finance`、`/finance/[source]`、首页摘要、来源白名单、迁移和 Cron。

## Verification

- RSSHub 官方仓库 `upstream/master` 已更新并固定到
  `bc8757ee58559c3e0b695e77a2cf8dec0ce956a8` 作为本次源码快照。
- 自建实例匿名探测于 2026-09-05 16:28（Asia/Shanghai）完成；41 条候选中 29 条返回 200 与非空 RSS。
- 推荐财经六来源全部返回 200，共 88 条且 88 条带发布时间。
- 未调用生产 API、Supabase 或 Cron；未读取、输出或提交任何秘密。

## Review

- Standards：调研遵守新来源生产门禁的第一步，只做无凭据上游探测；没有越过部署、云端迁移和手动生产
  写入验证直接配置 Cron。
- Spec：用户要求研究“还有什么分类可以抓”，文档给出七类候选、实测矩阵、优先级和明确下一步，没有
  擅自实现未确认分区。
- Rejected：未推荐需要 `SMZDM_COOKIE` 的什么值得买排行榜，也未把 503、超时或空字段来源包装成可用。

## Risks

- 上游站点和 RSSHub 路由没有 SLA，本次结果只证明当前时点可用。
- 财经快讯变化快，未来 Cron 频率需要结合抓取耗时、上游缓存和云端运行记录确定。
- 排行榜经常缺少发布时间；若后续实现影视或 Steam，数据模型和 UI 必须区分 `published_at` 与批次
  `fetched_at`。
- 财经内容属于信息聚合，不应在 UI 中呈现投资建议、收益暗示或自动交易信号。
