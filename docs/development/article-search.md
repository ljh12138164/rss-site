# 文章搜索

## Background

用户确认 Pagefind 风格弹窗，搜索已保存标题和摘要，无独立搜索服务或定时索引发布。

## Scope

全站入口、桌面弹窗、移动宽面板、300ms 防抖、命中摘要与高亮、分页、空态、失败重试。

## Out of scope

原文抓取、语义搜索、全站改版、生产部署。

## Acceptance criteria

至少两个字符搜索公开文章，20 条一批；中文组合输入暂停查询，过期请求取消。
高亮不注入 HTML；手机、桌面、明暗主题与 Tab/Enter/Esc 可用。

## Feasibility

可行。复用 signal_articles 公开 SELECT、publishable key、Next 16.3.4、React 19.2.8、React Aria 1.17.0、Tailwind 4.3.3。
不改数据库权限。无独立正文，不宣称原文全文搜索。ILIKE 子串搜索按发布时间排序；5 秒超时、80 字符限制、30 秒缓存。

## Implementation

- 已通过 UI Skills MCP 完整读取 interface-design 与 baseline-ui；用户确认弹窗。
- 复用 SiteShell、ActionButton、冷蓝强调、纸白/墨色/夜色/灰色 tokens、中文系统字体及 4px 间距基础。
- 读者寻找文章；输入为焦点、标题突出、来源时间弱化；命中片段帮助辨识内容，无图、无卡片网格。
- React Aria 管理焦点和 Esc；结果用 Tab/Enter 访问。
- PostgREST 值加引号并转义 LIKE 通配符；星号因上游别名语义明确拒绝。
- 每次读取 21 条判断下一页，最多浏览 1000 条，显示已加载数量；动态分页前端去重。
- 用户要求留在 feat/section-rss-feeds，已切回；误建分支无独有提交。

- 本次涉及的 6 个代码文件及开发文档通过 Biome 格式和 lint 检查；全仓非格式 lint 通过。全仓格式检查受当前工作树既有 CRLF 换行影响，会要求机械改写 63 个非本次文件，因此未扩大改动范围。
- 全仓类型检查通过：API 与 Web 共 2 个任务。
- 全仓测试通过：API 54 项，Web 67 项；新增 7 项覆盖查询边界、PostgREST 保留字符、摘要截取、安全高亮、接口分页和错误隐藏。
- Web 生产构建通过，生成 39 个路由；`/api/search` 为动态 Route Handler。
- 使用云端只读数据验证 `模型` 返回 20 条并有下一页，响应约 11KB；`10%`、引号/逗号及无结果查询均返回合法 JSON，未暴露数据库错误。
- 在本地页面实际检查桌面和 390×844 手机宽度、明暗主题、自动聚焦、单次 Esc 关闭与焦点返回、清空、空结果、关键词高亮及“显示更多”。

## Review

- Standards：只新增一个服务端查询路由和一个 React Aria 弹窗组件，复用现有来源注册、按钮、主题与外链中转；未增加依赖、数据库写入或平行设计系统。
- Spec：搜索入口、300ms 防抖、标题与摘要匹配、紧凑片段、高亮、分页、加载/空态/错误态和键盘操作均完成。
- 性能复核后把可能很长的摘要截取移到服务端，避免先向浏览器传完整正文式摘要；查询以 21 条前瞻判断是否还有下一页。
- 安全复核覆盖 PostgREST 过滤字符、LIKE 通配符、React 文本转义、查询超时和客户端不可见的错误详情。
- 没有阻塞问题或需要另建 roadmap 的已接受后续；正文采集和数据库索引仍明确在本次范围外。

## Risks

无索引子串检索随数据增长需复测；动态 offset 分页可能跳过条目。仅标题和摘要，不含未入库正文。
