# 财经热点来源

## Background

AI 继续作为站点主要分区，财经作为第一批新增辅助信息。来源来自已经完成的匿名 RSSHub 探测，页面沿用
现有 React Aria 交互与平面信号台视觉，不引入新的组件库，也不生成占位新闻或假封面。

Roadmap：[辅助热点分区 roadmap](../roadmaps/additional-hot-categories.md)。

## Scope

- 注册华尔街见闻、财联社、金十数据、第一财经、证券时报和同花顺财经六路来源。
- 新增 `/finance`、`/finance/[source]`、加载态、导航、首页辅助摘要和安全离站返回。
- 扩展 Hono 分区入口、Supabase 来源/分区约束和 pgTAP 覆盖。
- 将 AI 调整为每 2 小时采集，其余分区调整为每 6 小时，并保持至少 5 分钟错峰。
- 将来源 Cron 改为不含频率的稳定任务名，验证全部来源后清理旧的五小时任务并调度新任务。
- 部署后严格执行六路财经的云端 Supabase 生产数据门禁，全部通过才启用 Cron。

## Out of scope

- 跨平台财经综合排名、投资建议、收益暗示或交易信号。
- 游戏、体育、影视文化、科学研究、生活消费与汽车页面。
- 为没有图片的财经快讯生成假封面。
- 在代码合并和生产部署前写入云端 Supabase 或提前启用财经 Cron。

## UI surface

- Entry points：首页 AI 主位之后的辅助分区、主导航、`/finance`、六个来源详情页。
- Visual system：复用现有窄边框、来源编号、频段条和等宽辅助信息；财经不增加独立品牌色。
- States：沿用每来源 ready / empty / error 与路由 loading skeleton；真实数据未写入时显示空态。
- Responsive：保持现有桌面双列与移动单列行为，不新增横向滚动区域。
- UI Skills fallback：当前环境没有暴露 UI Skills registry，采用 `frontend-design`、仓库现有组件和 UI 质量
  清单作为验收基线，不声明 UI Skills 审查。

## Feasibility

结论：可行。

- 六路匿名 Feed 已实测为 HTTP 200 与非空，合计 88 条且全部带发布时间；通用 RSS 解析器无需新增格式分支。
- 现有来源注册、分区查询、来源详情和空/错状态均可扩展，不需要引入 UI 或运行时依赖。
- 主要技术难点是频率变更后的旧 Cron 残留。任务名改为稳定的 `signal-ingest-<source>`，且只在 36 路
  云端验证全部通过后，精确清理已知旧任务名；以后调频不会再次更名。
- 财经与游戏合并后的调度每天共 192 次来源触发：AI 72 次，30 路辅助来源 120 次。每次启动至少相隔 5 分钟，远低于
  Supabase Cron 的并发建议；仍需用生产运行记录观察单次上游延迟。

## Implementation

- 首页顺序调整为 AI、科技、国内新闻、社交、财经，AI 明确作为主信息面；辅助分区继续复用相同信号带，
  不增加跨平台权重或综合榜。
- 导航移除重复的“首页”文字入口，站点标识继续返回首页，以给移动端新增财经入口留出宽度。
- AI 来源卡和页面显示 2H，其余显示 6H；数据库实际时间仍来自 `source_status`，不显示虚假倒计时。
- 财经六路按 UTC 02:30–02:55 起始并每 6 小时重复；AI 占偶数小时 00–25 分钟，其余辅助分区使用相邻
  时段，保留至少 5 分钟间隔。每日清理移到 UTC 05:30，避开来源任务。
- 新增 `/cron/finance/:source` 与通用 `/cron/signals/:source` 白名单、前后端来源注册、Supabase 约束和
  公开只读查询；所有页面在没有生产数据时继续显示真实空态。

## Acceptance criteria

- 六路来源均能通过通用解析器进入 `finance` 分区，未知来源和错分区请求返回 404。
- 页面只读取 Supabase 真实数据；空库显示明确空态，不包含模拟财经条目。
- 首页首先呈现 AI 分区，并能访问财经总览、来源详情和安全离站页。
- API、Web、迁移约束与 Cron 配置对 36 个来源保持同一白名单。
- AI 六路每 2 小时采集；其余 30 路每 6 小时采集；全部来源至少错开 5 分钟且不与清理任务冲突。
- `setup:cron` 在所有来源完成部署后云端写入核验前，不安装扩展、不更新 Vault，也不更新或删除任何既有
  Cron。
- 单元测试、格式、lint、类型检查、生产构建和可用的数据库测试通过。

## Production gate

1. 当前匿名探测证据已记录；部署后再次确认六路 Feed 可读。
2. 部署 API，并应用版本化迁移到关联的云端 Supabase；前端服务器上线不阻塞采集门禁。
3. 使用服务端 `CRON_SECRET` 逐一调用生产 `POST /cron/signals/:source`。
4. 查询云端 `ingestion_runs`、`source_status`、`hot_items` 与 `signal_articles`，核验批次、条数、标题、URL、
   分区、排名、时间和持久化关联。
5. 全部通过后运行 `pnpm setup:cron`，确认新任务 active、使用 Vault 秘密且旧五小时任务已移除。
6. 将不含秘密的 HTTP 状态、条目数、批次 ID 和时间戳补回本文。

## Verification

- 2026-09-05 19:25 CST 对 `https://rss.ljhboard.cn` 匿名复探：六路均为 HTTP 200 与 RSS XML；条目数依次
  为华尔街见闻 10、财联社 13、金十数据 1、第一财经 30、证券时报 10、同花顺 20。
- 本地 API 52 项与 Web 42 项 Vitest 全部通过；`pnpm lint`、`pnpm typecheck` 和 `pnpm build` 通过。
- 财经迁移已于 2026-09-05 应用到云端；P1 历史回填得到 496 条 `signal_articles`，现有 496 条
  `hot_items` 均存在文章关联且来源、来源键和分区一致。
- 第一次全源门禁在掘金瞬时 503 处停止；第二次前 26 路成功，随后金十数据因首条 `<link/>` 为空返回
  502。公开 Feed 同时包含仍可用的真实文章，因此本分支让通用解析器跳过无标题或无 Web URL 的坏条目，
  仅在整份 Feed 无可用项时失败。
- 生产 Cron 未更新：云端仍保留 24 路既有五小时采集任务和 1 个清理任务。当前解析修复合并并部署 API 后，
  必须从第一路重新运行完整门禁，不能把本次部分成功视为财经验收完成。
- pgTAP 已扩展到 53 项，覆盖财经/游戏白名单、持久化表、RLS 与公开角色只读权限；本轮不以本地 Docker
  代替云端验证。

## Review

- Standards：来源白名单在 API、Web、迁移与 Cron 中一致；所有生产写入仍经受保护 Hono 入口，公开客户端
  只有 RLS 读取权限。审查中修正了验证前更新 Vault 的顺序问题，现在任一来源失败时不修改扩展、Vault 或 Cron。
- Spec：六路来源、真实空态、2H/6H 错峰、AI 首页主位和部署后云端门禁均与范围一致。
- UI：复用现有语义 section/nav、React Aria 主题交互和响应式网格；SSR 测试覆盖入口与真实空态。遵照用户要求
  未操控桌面浏览器，本轮不声称完成交互式截图审查。
- Rejected：未加入跨平台综合排名、投资建议、假封面或提前写入生产数据库；这些都不属于本阶段。
- Accepted follow-up：合并部署后的 Supabase 迁移、真实批次核验、Advisors 与 Cron active 证据必须回填本文。

## Risks

- 财经路由包含实时快讯和编辑头条，不应统一宣传为算法热榜。
- 36 路任务虽然低于 Supabase Cron 并发建议，但上游超时仍可能跨越下一分钟；API 的请求超时和 5 分钟错峰
  是主要隔离手段。
- 更名 Cron 时必须只清理本项目已知的旧任务名，不能操作用户的其他 Supabase Cron。
