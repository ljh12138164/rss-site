# AI 分区首页查询的行数估算

## Background

[首页分区预览索引](home-preview-published-index.md) 已在生产生效。五个分区按发布时间索引直接取最新 3 条。AI 分区同时过滤 `section` 和 `source`，生产规划器估计匹配 9 行，实际扫描 915 行再排序。本地重现同类误差。按现有数据库约束，每个来源属于一个分区。

## Scope

通过业务迁移补充 PostgreSQL 的 `section` 与 `source` 依赖统计，帮助查询规划器估算首页预览的候选行数。基线是含 PR #134 的 `master`（`6434fdf`）。

## Out of scope

增加索引、修改首页 SQL、改变来源筛选或排序、调整全库统计参数。

## Acceptance criteria

- 代表性 PostgreSQL 18 数据上，AI 分区优先使用现有发布时间索引，查询结果与次序一致。
- 生产发布 SQL 可正常回放。首次执行收集依赖统计，重复执行复用已收集的数据，恢复出只有定义的统计对象时可补齐数据。
- 其余五个分区继续返回同样结果，并使用现有发布时间索引。

## Feasibility

`CREATE STATISTICS (dependencies)` 让规划器识别来源与分区的依赖关系。复现中默认单列统计估算 10 行，候选实际为 905 行。增加依赖统计后估算约 937 行，AI 直接按现有索引取 3 条。仅使用默认 MCV 统计的对照组仍选旧计划。

## Implementation

新增 `027-home-preview-source-statistics.sql`，只在依赖统计尚未收集时分析所需的两列。后续沿用 PostgreSQL 的常规分析与刷新机制。

## Verification

- PostgreSQL 18 约 8.5 万条模拟数据，应用只读角色执行实际首页查询。运行迁移前 AI 估算约 9 条并排序，运行迁移后估算约 911 条，使用现有发布时间索引直接取 3 条。六个分区的返回结果与顺序全部一致，均使用发布时间索引。
- 对已收集依赖统计重复执行迁移，统计记录元组版本未变。模拟恢复后统计只有定义的情况，迁移重新收集并恢复索引计划。
- 本地仓库 PostgreSQL 镜像加载 pg_cron 和 pg_net，使用渲染出的完整发布 SQL 回放两次成功。评审未发现阻塞项，无衍生路线图。

## Risks

首次分析会抽样读取文章表。查询规划器会随生产数据和成本估算选择计划，最终命中及耗时以上线抽样为准。
