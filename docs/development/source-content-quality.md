# 来源内容质量修复

## 状态

进行中。

## 目标

- 从 API、Web 来源导航、Cron 配置和数据库允许值中移除 V2EX、同花顺与 Steam。
- 保留 GitHub Blog 的官方 RSS 地址，不为它改接 RSSHub。
- GLM 发布条目保留用于区分版本的 URL fragment，避免多个发布日期折叠成同一链接。
- 解码 Feed 标题中二次编码的 HTML entity，避免英文标题显示 `&#39;` 等乱码。
- 在独立 RSSHub 仓库修复中新网视频页正文提取，并用真实页面结构回归。

## 已确认的边界

- 当前所有配置了 `rsshubPath` 的来源都未使用 `mode=fulltext`；GLM、Google AI、GitHub Blog 是官方 Feed 直连。
- `mode=fulltext` 是逐条追加详情页请求的通用中间件，不是“RSSHub 默认就该返回全文”的开关。实测 Steam 三条请求会超过 25 秒，因此本轮不全局开启。
- 删除来源表示停止展示与采集，并通过版本化迁移清理这三个来源的线上数据。迁移不会在分支合并与部署前直接应用到生产库。
- 中新网视频页正文由脚本动态注入 `<video>`；现有 `div.content_desc` 只包含责任编辑，不能作为视频正文。
- 本轮可见 UI 仅删除三个来源入口，不引入新布局或样式。UI Skills registry 未提供可用指南，沿用现有设计系统和 UI quality 清单。

## 验收标准

1. 三个已删除来源不再是合法 API/Web 来源，旧 Cron 名会在下次安装时被取消。
2. 数据库迁移先取消对应 Cron，再清理关联热榜、状态、文章和运行记录，最后收紧来源约束。
3. GLM 同一页面的不同 fragment 可作为不同条目保存；普通来源继续去掉无意义 fragment。
4. 二次编码的英文标题 entity 被解码，原始正文 HTML 仍按现有规则保存。
5. 中新网视频页输出可播放的直接 MP4，而不是只有责任编辑。
6. 相关单测、类型检查与格式检查通过；两个仓库分别提交并推送独立分支。

## 交付顺序

1. 先合并并部署 RSSHub 修复。
2. 再合并并部署本站 API/Web。
3. 最后应用 Supabase 迁移并验证三个 Cron 和来源数据已经移除，再重采集 GLM 与中新网。
