# 首页顺序列表与分区局部加载

## Background

用户要求首页新闻沿用平台页的顺序列表，并增加平台标识；切换各分区平台时避免全页骨架屏。继续在 `feat/section-rss-feeds` 实现。

## Scope

首页六分区文章列表、六分区共享导航布局及文章加载状态。复用 `home-article-list.md`、`source-platform-icons.md` 与 `chronological-feed-dates.md` 的已确认页面范围、时间排序、图标和响应式设计。

## Out of scope

新来源、数据库、抓取、Cron、部署、合并；不修改既有每来源一条的首页查询范围。

## Acceptance criteria

- 首页复用 `HotList`，按各分区已有发布时间顺序连续编号，附可点击的平台图标和名称。编号只是列表位置，不作为跨平台热度排名。
- 国内新闻详情和外链中转行为保持；空态、错误及部分成功仍展示真实结果。
- 六分区标题、面包屑和平台导航位于持久化布局；文章数据等待时只有内容区显示骨架屏。当前平台、浏览器前进后退、手机横向导航保持正常。
- 新闻文章详情保持独立阅读布局，不重复嵌套导航和 SiteShell。
- Web 测试、类型、生产构建及桌面/手机明暗主题检查通过。

## Feasibility

可行。项目使用 Next 16.3.4、React 19.2.8、React Aria 1.17.0、Tailwind 4.3.3 与 Lucide。已读取本地 Next loading 和导航文档：`loading.tsx` 覆盖同层 page 及嵌套内容，但不覆盖同层 layout。

根因：每个异步平台页等待数据后才返回包含 SiteShell 和 SourceNavigation 的完整页面；共享 SectionLoading 同时将标题、导航和列表替换成骨架。

方案：把无需数据请求的标题、来源导航及外壳提升到分区 layout；服务端 page 保持数据查询和文章呈现。小型客户端布局仅用 pathname 选择现有来源元数据，不在客户端重新取文章。新闻更深层详情沿用自己的布局，防止嵌套 main。

## Implementation

- Intent：读者快速扫读各分区文章、切换来源，标题作为焦点，编号/平台/日期为辅助信息。
- 复用现有 HotList 的字号、4px 间距基础、细分隔、蓝色强调和背景/卡片语义 token；不引入视觉依赖或新交互模型。
- UI Skills：取得 `dammyjay93/interface-design`、`ibelick/baseline-ui`；沿用现有视觉方向，覆盖桌面、手机、键盘及明暗主题。
- 首页保留分区目录及容器，只替换文章行；平台标识单独链接，避免嵌套链接。组合来源与 sourceKey 作为 key。
- 首页继续省略作者并限制摘要为 240 字符，避免上游长作者字段扩大列表；共享日期固定为北京时间及 00–23 时制，保持原首页时间语义。
- 平台导航保留在同一布局内；数据状态移到导航下方文章区，避免加载影响导航。
- 原有 next-env.d.ts 变化确认为 Next dev 自动生成的类型路径，不作为产品修改提交。CONTEXT.md 不存在，依据 HERMES.md 与现有开发文档继续。

## Verification

- 修改前新增两项断言分别在首页缺少 ol 顺序列表、加载组件包含整页导航处失败。
- `pnpm --filter @rss-site/web test`：28 个测试文件、75 项通过，包含六分区在文章加载时仍展示当前平台与导航、详情布局不嵌套、顺序列表与错误状态。
- `TZ=UTC pnpm --filter @rss-site/web test components/hot-list.test.tsx`：先观察旧共享格式器将 01:00 UTC 显示为 01:00 的回归，再验证固定北京时间后显示 09:00，两项通过。
- `pnpm check-types`：Web 与 API 均通过；`pnpm --filter @rss-site/web build`：生产构建通过，路由保持 39 个。
- 本次 40 个 Web 文件 Biome check 通过，`git diff --check` 通过。全仓 `pnpm lint` 仍有 82 个未改文件的既有 CRLF 格式诊断；清理期间恢复了这些文件的原始行尾，不纳入此次提交。
- 生产模式本地浏览器真实数据：1280px 桌面、390px 手机明暗主题首页均有 26 条文章及 26 个平台链接，无横向溢出。截图位于本任务的本地 visualizations 目录。
- 对六个分区的 RSC 导航增加 1.6 秒延迟：均观察到文章骨架；平台导航和 main 的 DOM 对象保持同一实例，标题保持可见、选中平台正确，返回全部正常。财经首次检查因上游读取超过 20 秒超时，复测放宽为 60 秒后正常完成。
- 390px 手机上挂起央视请求，再点击界面：可中断切换，最终标题和选中项为界面，旧响应不会覆盖新选择；导航实例不变，无横向溢出，明暗加载截图通过；前进后退及键盘聚焦通过。
- 新闻来源进入真实文章详情只有一个 main，没有重复平台导航；完成的浏览器检查无 pageerror。
