# B 站视频阅读页

## Background

B 站热门 Feed 提供视频 ID、封面、简介和 UP 主。文章正文清理会删除原始 iframe，只有短横线简介的条目因此几乎空白。参见[播放器接入调研](../research/bilibili-player-embedding.md)。

## Scope

在现有 `/social/bilibili/[slug]` 阅读页中保留标题、UP 主、封面和 B 站原视频链接。用户点击封面后加载官方播放器。简介为空或仅为 `-` 时隐藏。

## Out of scope

B 站采集路线、入库、榜单和分区导航。

## Acceptance criteria

- 桌面和窄屏均显示封面、播放按钮、UP 主和「去 B 站观看」。
- 仅使用可验证的 B 站 BV/av 链接构造 iframe。保留有效分 P，无法解析时保留封面与原视频入口。
- 播放器在用户点击前不加载。空简介不显示占位段落，正常简介继续显示。

## Feasibility

现有文章表已保存封面和视频链接。官方桌面播放器接受 BV/av；Android Chromium 模拟会导航到 B 站的移动播放器。两条路径已在窄范围 CSP 下测试，因此不需要直抓视频地址或额外播放器依赖。

## Implementation

文章读取器取出已存封面，以站内样式显示 16:9 视频区域。只有 B 站来源会挂载该组件，iframe 由组件生成。CSP 允许 B 站桌面和移动播放器的精确路径，通用 Feed HTML 清理规则保持原有行为。CSP 适用于站内客户端导航后的阅读页。

## Verification

- 在本地 Next 应用中使用真实 B 站视频和 Feed 封面验证阅读页。桌面 Chromium 点击封面后开始播放。Pixel 7 模拟加载官方移动播放器，在播放器内点按后播放进度正常前进。
- 桌面与移动视口均有封面、UP 主和原视频入口，点击前未挂载 iframe，横杠简介未渲染，页面无横向溢出。正常简介可见，无法解析视频 ID 的条目保留原视频入口且不挂载播放器。
- 校验了站内返回的 CSP 头。测试覆盖 BV/av、分 P、无效来源 URL 和空简介。
- 合入 `master`（`e36cc37`）后，Signals 9 项、API 131 项和 Web 249 项测试通过，另有 24 项按原配置跳过。三包类型检查、Biome 和 Web 生产构建通过。

## Risks

播放器由 B 站托管。测试中出现过第三方加载超时。登录、地区、版权和浏览器限制可能影响个别视频，原视频入口始终可用。移动端验收使用 Chromium 设备模拟。
