# 分区与来源列表滚动加载

## Background

用户要求各分区也具备首页的滚动加载，继续当前分支；沿用跳过测试与构建的要求。

## Scope

AI、科技、国内新闻、社交、财经、游戏六个总览，以及全部来源详情页接入统一服务端首屏与游标分页。文章读取已收录的 signal_articles，不再局限于当前 hot_items 快照。

## Acceptance criteria

- 每页 30 条，接近底部自动加载；手动加载、失败重试、末页和空态可见。
- 分区与来源条件同时作用于首屏和后续请求；来源必须属于指定分区。
- 发布时间倒序，日期相同按 ID，空日期最后；切换来源重新建立列表状态。
- 新闻保持站内详情，来源链接和离站返回路径保持所属分区。
- GitHub 开源榜按当前榜单 position 续取，同一批次分页，不混入历史项目。

## Feasibility

复用首页 /api/articles、现有公开只读查询与 HomeArticleList，不新增依赖、数据库结构、权限或 Cron。分区/来源白名单与游标校验在 API 层执行。

## Implementation

后续用户要求首屏后预取下一页。现有项目未安装 React Query，沿用 fetch 与 IntersectionObserver；共享组件每次显示一页后后台预取一页，触底复用已完成的数据或进行中的同一 Promise。预取不追加可见内容，因此不会连续预取全部页面；预取失败不打断阅读，触底时重试。卸载取消请求并清空缓存，缓存键包含分区、来源与游标。

新增 PaginatedArticleFeed 服务端组件，为各路由读取首屏并隔离错误。HomeArticleList 增加 section/source 参数，使用带范围的 key 在导航时重置列表、取消旧请求；详情页隐藏重复的平台标签。各分区保留现有标题、导航、骨架和视觉风格。科技总览为文章列表，开源榜仍由现有来源导航独立进入。

GitHub 查询 hot_items，游标包含 batch_id 和 position；正在阅读的快照被采集替换后旧批次不再有后续数据，刷新榜单即可查看最新一批。其他来源沿用首页的历史文章时间游标与首次读取时间上界。

## Verification

按用户要求未运行测试、类型检查、生产构建或浏览器测试，仅静态阅读及格式化。现有以旧 View 夹具为基础的测试不覆盖新异步分页路由，不宣称验证通过。

## Risks

真实请求与滚动交互尚未运行验证。首次查询失败可重试；下一页失败保留已有文章。已有文章的发布时间发生变更时分页位置可能变化，刷新可重新排序。

## Review

静态检查涵盖范围白名单、分页顺序、日期空值、请求取消及来源切换。无额外已接受的后续功能，不创建空 roadmap。
