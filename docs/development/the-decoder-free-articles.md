# The Decoder 采集公开全文

## 背景

The Decoder 的 WordPress API 向匿名客户端返回付费文章元数据，正文 `content.rendered` 为空。2026-11-21 的本地 RSSHub 与线上 RSSHub 各返回 100 篇，相同的 22 篇为空。站点原采集 URL 返回 30 篇，其中 7 篇无正文。

## 范围

调整 The Decoder 的订阅 URL。每批优先选取可公开获取正文的文章，按 Feed 顺序最多保留 30 篇。历史归档及付费文章摘要回填在本次范围之外。

## 验收

- 匿名访问过滤后的线上 RSSHub，确认能提供至少 30 条唯一且有正文的候选。
- 经 `ingestSignal` 验证前 30 条保持原顺序，库表写入所接收的正文均非空。

## 可行性与实现

现有 RSSHub 支持通用参数 `limit` 和 `filter_description`。过滤在候选获取后运行。`limit=60` 增加选取范围，`filter_description=^\s*<` 保留以 HTML 标签起始的正文，同时避开 RSSHub 在正文为空时使用的纯文本标题。`itemLimit=30` 继续在站点采集时截取。采集入口与既有 Cron 清单的任务路径没有变动。

## 验证

- 2026-11-21 匿名请求原 URL 和过滤 URL 均返回 HTTP 200。原 Feed 含 30 条、7 条空正文。过滤后的 Feed 含 49 条、零空正文。使用变更后的来源配置和实际采集器取得前 30 条，URL 全部唯一，按发布时间顺序排列，渲染后正文长度为 830–12,236 字符。模拟零条目 Feed 时记录了一次失败，未写入替换批次。
- `pnpm check-types` 三个包均通过。`pnpm test` 共 330 项通过，22 项依赖数据库或 Redis 的测试在本地跳过。变更文件的 Biome 检查和全仓 lint（关闭 formatter）通过。Windows 工作区已有文件使用 CRLF，全仓的格式检查交由 CI 核验。
- 已按采集目标和仓库规范核对差异。Codex CLI 的分支审查无法在本地启动 `git diff`，改为直接提供完整的配置差异和实测结果，审查没有阻塞项或需另列路线图的事项。

## 风险

RSSHub 过滤正文 HTML 形态，依赖 The Decoder 当前通过匿名 API 将付费正文留空，以及公开正文以 HTML 返回。如果一批可选正文不足 30 篇，站点会发布较短的列表。过滤结果完全为空时，现有采集失败流程会保留上一批发布结果。
