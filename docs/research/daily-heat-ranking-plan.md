## 1. 推荐结论

采用“**事件归组 → 内容资格检查 → 代码计算热度 → 按指数取前列 → 撰写事件摘要 → 发布固定顺序**”。模型判断哪些报道讲的是同一件事、事实是否够写、怎样概括；热度、顺序、头条和统计由代码确定。

AIHOT 的热榜以独立参与方和时间衰减计分；其日报另有编辑重要性公式，混合最高编辑分、当日参与方、一手性和跟进扣分。本方案按用户目标采用前者作为日报主排序，不把两种分数混为一谈，也不让模型自由报一个“热点指数”。[热榜实现](https://github.com/KKKKhazix/AIHOT/blob/ad3e934d376e4399ce350d981b4b5eb7a61f860e/packages/backend/src/events/hot.ts#L139-L189)，[上游日报公式](https://github.com/KKKKhazix/AIHOT/blob/ad3e934d376e4399ce350d981b4b5eb7a61f860e/packages/backend/src/reports/edition.ts#L326-L334)。

## 2. 指数怎么计算

固定统计时点为该期的材料窗口终点 `T = windowEnd`，保留本站前一自然日口径。该期只选覆盖日有新事实的事件；热度可引用截止 T 的前 48 小时报道，帮助衡量跨日持续讨论。

对一个事件的每个去重参与来源，只保留窗口内最新有效报道时间 t：

```text
原始热度 H = Σ 2 ^ (−报道距 T 的小时数 / 24)
展示指数 = round(H × 100) / 10
```

- 本站建议统一使用半开区间 `[T−48h, T)`，与日报日窗一致，恰好在 T 发布的文章留给下一期；上游热榜实际为 `(T−48h, T]`，此边界调整是本站选择。
- 有可信发布时间就用发布时间；缺失时用首次收录时间。反复采集不得使用 `last_seen_at` 刷新热度。未来时间不能通过换成采集时间悄悄变成当前证据。
- 排序用未舍入的 H，展示值只保留一位小数；同分按最新有效证据时间，再按冻结事件键稳定排序。
- 单来源的可信新事件也可入日报，热度较低。上游热榜的“至少两个参与方”不直接用来禁止单一官方来源的日报消息。
- 来源热度衡量本站看到的传播覆盖，不等于事实真实性、报道质量或全网阅读量。

以下是公式演算，不是真实新闻数据：

| 情形 | 贡献或指数 |
| --- | --- |
| 一个参与来源刚刚报道 | 10.0 |
| 同一来源发十篇，最新一篇刚刚报道 | 仍为 10.0 |
| 一个来源在 24 小时前报道 | 5.0 |
| 三个来源分别在 0、6、12 小时前报道 | 合计约 25.5 |

每期保存 T、取材快照时点 S、计分规则版本和来源身份映射版本。允许在首次冻结前收集迟到材料，但只使用源时间落在窗口内、且在 S 前已知的证据；一旦冻结，重试不加入新文章，不按实际重试时刻重算指数。

## 3. 先解决事件和来源去重

### 同一事件的边界

同一主体、动作、产品/版本、阶段一致，并有正文或摘要支持，才合并报道。下面几种情况应分开：

- 同公司发布两个不同产品。
- 产品预告、正式发布、随后第三方测试。
- 同一模型开放 API，与后来降价。

先通过 URL 规范化、正文指纹、实体与产品名缩小候选，再对不确定关系做有证据的判断；标题相似不能直接证明同一事件。无法确认时拆开，记录未判定；不能为提高指数硬合并。多事件综述不得未经拆解就给每个提到的事件加热。

首版建议只做**每期内的事件归组快照**。不先复制 AIHOT 的全站向量库、长期事件图谱、实时趋势和管理后台。后续如果需要跨期事件持续跟进，可再评估稳定的全局事件身份。

### 参与来源的边界

第一版以已配置的发布主体映射为准：同一家机构的多个频道合并计一方。同一报道的重复抓取、镜像 URL 不增加贡献。不能仅凭域名推断媒体所属，也不能把“多个网站转载”描述成“多方独立证实”。

本站 registry 已有 source ID，但没有 AIHOT 那样完整的 owner/group/社区作者身份模型。无法可靠归属的社区来源先按平台计一次，避免根据可变作者字符串虚增参与人数。对外建议称“本站来源热度”，展示“参与来源数”，不标“全网热度”或“独立验证方数”。

计分证据与正文引用分开：一个事件可以有十个参与来源，正文只引用最能支持摘要的一至三篇站内文章。不能把 `sourceIds.length` 当作热度，因为现有引用上限是三篇。[当前引用约束](/D:/code/rss-site/shared/daily-report.ts:102)。

## 4. 为什么不能只在现有输出后加 sort

目前候选查询按时间取每来源四篇、每分区八篇、总计四十八篇；再经过正文清洗、去重和 64KiB 预算淘汰。热门但较早的事件可能没有进入模型，后续排序无法找回。单篇正文只取前 1800 个 Unicode 字符，也可能遗漏关键阶段和限制。[候选查询](/D:/code/rss-site/apps/web/lib/daily-repository.ts:77)，[材料冻结](/D:/code/ai-base/apps/agent-service/src/daily-report/materials.ts:43)。

现有 `ai_events` 包含按文章自动创建的事件，不代表已经完成跨来源聚簇，不能直接对其关联数求热度。[自动事件触发器](/D:/code/rss-site/deploy/postgres/baseline.sql:93)。

推荐数据流：

```text
48 小时有效文章元数据，按稳定游标分页读取
  → 去重、归一来源身份、确认事件关系
  → 找出覆盖日有新增事实且证据可写的事件
  → 对事件的全部有效证据计算热度并固定排序
  → 按排序依次准备摘要，失败时有界重试或换取下一合格事件
  → 按已固定的顺序组装头条、正文、导读及站内引用
```

先分页遍历时间窗，不用每来源/分区固定数量截断来估计热度。每页和模型请求仍需预算上限；如果触及整体扫描上限，应标为覆盖不完整，不把局部排名当作完整排名发布。材料仍需满足基本可读性及引用要求，标题空壳或错误页不得参与增热。

每代表来源最多两条的旧规则需要重新定位：如保留，它是**选刊时的多样性限制**，不得改写事件本身的指数。页面应说明“按热度排列的精选”，而不是声称列出了全部事件严格 Top N。本方案建议先保留该既有选刊约束，合格入选事件之间仍按 H 降序。

## 5. 最小改动边界与技术难点

| 部分 | 需要承担的工作 |
| --- | --- |
| rss-site 内部数据接口 | 分页读取有效元数据，按入选证据 ID 读取正文，保存并验证任务快照；不把数据库凭据交给模型服务 |
| ai-base runner | 归组与编辑阶段、冻结阶段结果、有限重试与恢复；继续使用既有常驻 runner 和租约 |
| 确定性计分模块 | 去重参与来源、时间衰减、证据边界、稳定排序，模型不得提供或覆盖分值 |
| 成品协议与页面 | 兼容已有 v1 日报；新报保存指数、参与来源数、截止时点和规则版本，按固定顺序展示 |

关键限制：

1. **冻结体积。** 现有任务 `input_snapshot` 上限 256KiB，不能把两天全部材料和聚簇证据强塞进去。建议把较大的候选/证据按任务分行保存为私有快照，原快照只保留阶段摘要和引用；具体表结构需由样本规模决定。实现时需要版本迁移和旧任务兼容设计。
2. **执行时限。** 当前整次任务 150 秒、单次 Gemini 45 秒。加入归组与逐事件写作后，不能假定仍可一次完成。先测实际材料量及耗时；优先按持久阶段恢复，保留各阶段有限预算，而非无上限拉长请求或引入第二套调度。
3. **分组稳定。** 模型重跑可能改变成员关系。必须冻结已确认的成员和来源映射，分数才可重现；模型生成的摘要不得重新决定事件成员。
4. **采集健康。** 来源掉线会导致覆盖变小。先记录完整/缺失来源，首版不展示涨跌幅、热度走势或“爆”标签，避免把采集恢复当成突然爆热。
5. **质量与热度不同。** 未知引用、错误页、旧闻重复、无依据事实照常拒绝；不能以高热度放宽这些要求。

因此结论是：**方向可行，实施前需用真实历史样本确认候选规模、事件分组准确性和阶段预算**。这比增加一个排序字段更大，但不需要重建整个站点。

## 6. 推荐实施与验收顺序

1. **离线影子计算。** 选取一段含安静日、密集发布日和同事件多源报道的历史材料，不发布、不改旧日报；人工标注同事件/不同事件及来源别名，再对照指数、排序和漏选情况。7 天作为建议起始样本，不是已完成验证。
2. **先验收分组与覆盖。** 优先发现错误合并、同机构重复计票、时间采样漏掉热点、扫描不完整这几类问题；记录无法判定样本。
3. **接入每日冻结与成品。** 新期使用新规则版本，既有期不自动重排或覆盖；模型按固定事件写摘要。保留站内引用和原文回退。
4. **部署后单期验收，再观察自然调度。** 核对任务、分数证据、顺序、摘要与页面一致；验证缺材料/无合格新闻/模型失败仍可区分。

必须具备的检查：

- 重复抓取不增热；同主体多渠道只计一次；不同主体不能误折叠。
- 同公司不同发布不误合并；无法判断的事件有记录。
- 24 小时贡献减半；48 小时及日窗边界、未来时间正确。
- 展示舍入不改变实际排序；同分和重试顺序稳定。
- 引用只展示三篇时，十来源证据仍完整参与统计。
- 热门事件不因较早发布时间被前置采样漏掉。
- 新成品指数与保存证据可复算；旧 v1 日报继续可读。
- 单来源可信新闻可以入选；覆盖不完整不会伪装成“当天无新闻”。

本轮只形成研究文档，没有执行以上离线样本实验，也没有新增接口、表、依赖、模型调用、Cron 或发布操作。
